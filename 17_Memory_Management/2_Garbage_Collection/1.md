### ============================================================
*** Garbage Collector GC ***
### ============================================================
1. Reachability: The "Root" Rule
The most important concept in JS memory is Reachability.

Everything starts at the Root (the Global Object, or window in browsers). 

If a variable can be traced back to 
the Root through a chain of references, 

it is "alive." 
If the chain is broken, it's garbage.

### ============================================================
2. The Main Algorithm: Mark-and-Sweep
As of 2026, 
almost all modern engines (V8 in Chrome/Node, SpiderMonkey in Firefox) 
use this strategy. 
It happens in two phases:

        Phase 1: Mark: 
            The GC starts at the Root and "paints" 
            every object it can reach. 

            It then looks at those objects' properties 
            and paints everything they can reach.

        Phase 2: Sweep: 
            The GC looks at the entire Heap. 
            Anything that isn't "painted" is deleted.

> [!NOTE]
> This is why "Circular References" 
> (Object A points to B, and B points to A) are no longer a problem. 
> If neither A nor B can be reached from the Root, 
> they both get swept.

### ============================================================
3. Generational Collection (The "V8" Optimization)
To make things faster, V8 divides the Heap into two "Generations":

        The Young Generation: 
            Where new objects are born. 
            Most objects die young (like temp variables in a function). 
            The GC cleans this area very frequently and very fast.

        The Old Generation: 
            If an object survives a few rounds of GC in the Young Generation, 
            it gets "promoted" to the Old Generation. 
            The GC cleans this area much less often 
            because it assumes these objects are "stable" 
            (like a long-running configuration object).

### ============================================================
4. Orphaning an Object
You don't "delete" an object in JS. You orphan it.
```js
let user = { name: "ArchUser" }; // Allocated
user = null; // The { name: "ArchUser" } object is now orphaned.
```
> [!NOTE]
> By setting user to null, 
> you broke the link from the Root. 
> In the next "Sweep," that object is gone.
